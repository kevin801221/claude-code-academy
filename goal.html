/goal 怎麼運作？

不是做一回合就停，而是每一回合結束後由 Haiku 檢查條件：還沒成立就繼續，成立才停。

02

用法

兩個指令就夠：設定目標、清除目標。

Claude Code
$ claude
> /goal <condition>
> /goal clear

需要 Claude Code v2.1.139+

完整行為請見官方文件。

  • 1/goal <condition> 讓 Claude 跨回合持續工作，直到條件成立。
  • 2條件是否成立，由小型快速模型（預設 Haiku）評估。
  • 3/goal clear 清除目前的目標。
  • 4與 /loop（時間驅動）和 auto 模式（逐工具）互補（見第 03 章）。

03

/goal、/loop、auto 模式

三種「讓 Claude 自己往前走」的方式，驅動力各不相同，彼此互補。

/goal條件驅動

跨回合持續工作，直到條件成立（由 Haiku 評估）。

/loop時間驅動

以時間為節奏，反覆觸發工作。

auto 模式逐工具

以每一次工具呼叫為單位運作。

三者互補，不是互相取代：/goal 管「做到什麼程度才停」、/loop 管「依時間節奏觸發」、auto 模式則落在「每一次工具呼叫」這一層。

該用哪一個？

依「驅動方式」判斷每個情境最適合哪一個。

04

社群技巧一：請代理自己提出目標

不知道該跑什麼 /goal？讓最了解你專案的代理先提案。

Alex Finn 在 X 上分享的做法：先請代理根據對你的了解，提出 3 個能長時間執行、產出最好成果的 /goal；選一個，再請它幫你寫 prompt。

貼文中提到：

  • Claude Code、Codex 與 Hermes agent 現在都有 /goal
  • 它讓代理能完成長時間執行的任務，有時長達數天
  • 建議挪出 15 分鐘做這件事
prompt
根據你對我、我的目標、企圖心，以及我們已經一起做出的東西的了解，現在有哪 3 個 /goal 是我們可以跑的、能長時間執行並產出最好成果的？

社群技巧二：讓代理幫你草擬 /goal prompt

已經有工作中的 session 與 repo？請代理深挖意圖，替你寫出 /goal。

Meta Alchemist 在 X 上分享的 Codex 技巧，同樣的思路也適用於其他支援 /goal 的代理：

  1. 請代理讀這個 session 和 repo，深入分析你想達成的確切意圖與目標，寫出對應的 /goal prompt；要求它深挖歷史與文件，做到 100% 清楚。
  2. 可以再加一句：不確定的地方，歡迎先問你幾個問題來釐清。
  3. 把代理給的內容複製貼上，把開頭改成 /goal。

貼文的說法是：這樣它就會完全照你在那個 session／repo 中想做的事去做，不間斷直到完成。

來源：Meta Alchemist (@meta_alchemist) on X
